# Monster Shop Idle (monster-shop-idle)

An idle clicker about running dodgy shops, named Monster Shop Idle (Rob's choice for the app as a whole; "Grizzle's Haunted Mall" is now just the first setting). Settings: a goblin in a haunted mall, an ex-smuggler on a space station, a pirate ship, a cyberpunk night market and a robot planet. Hobby project by Rob Stibal, inspired by the structure of the discontinued mobile game *It's Always Sunny: The Gang Goes Mobile* (schemes, episode-style prestige, character cards) but with an original setting and cast. Do not use that show's names or characters.

## Layout

- `index.html`: the whole game (HTML, CSS, JS in one file, no build step, no dependencies)
- `tools/sim.mjs`: balance simulator, run with `node tools/sim.mjs`. It reads the numbers straight out of `index.html` (`SCHEMES`, `MILESTONES`, `UPGRADES`, `SKINS` (for the first skin's shop names), `GOALS`, `STORY_GOALS`, `GOALS_NEEDED`, `CARDS`, `CHESTS`, `LEVEL_AT`, `LATE_LEVEL_STRENGTH`, `PERM_PER_EPISODE`, `EPISODE_COST_GROWTH`, `OFFLINE_CAP_S`, `BANK_BONUS`, `FREE_AUTO_SHOPS`, `EGGS_PER_GOAL`, `DAILY_CHEST`) with regexes, so keep those blocks in their current shape (`const X = [` ... `\n  ];`, and single-line number constants). It prints episode 1 in detail, then median times for several episodes in a row for engaged, casual and idle profiles (`node tools/sim.mjs [episodes] [runs]`; env vars `GROWTH`, `OFFRATE`, `OFFCAP`, `FREEAUTO`, `DAILY`, `UPGRADES=0`, `UPCOST`, `UPSPEC`, `LATELEVEL`, `STORY`, `BANK` try what-ifs). Session players (casual, idle) wait `tapWait` seconds (3, 5) before tapping a finished shop again; engaged taps at once.
- `README.md`: player-facing rules, card and chest tables, tuning pointers
- `manifest.webmanifest`, `sw.js`, `icons/`: make it installable as a home-screen app. The service worker is network first (cache only as the offline fallback), so pushes show up without cache busting; bump `CACHE` in `sw.js` if its file list changes. Icons are drawn by `tools/make_icons.py` (Pillow). The in-app browser pane can't register service workers, so test offline behavior in real Chrome. `theme-color` follows the skin's `bg` in `applySkin`.

## How the game works (current state)

- Skins: everything players read or see lives in `SKINS` (owner, words for customers, currency names, chest names, the cast on each card, shop hues, episodes with shops/story, and a `theme` of CSS variables plus a Google Fonts URL). Mechanics (`SCHEMES`, `CARDS`, `CHESTS`, goals) are shared, so saves work in any skin. Five skins: `mall` (Grizzle's Haunted Mall, Dripping ectoplasm palette: slime green and lilac on green-black with Rubik Wet Paint, which Rob picked on 2026-09-29 from 12 options over the earlier Moonlit graveyard with Alegreya), `starport` (Juno Vance on Starport Nine, navy/amber/teal with Russo One), and three added 2026-09-29 at Rob's request: `ship` (Captain Nell on The Salty Gull, Jolly Roger black/bone/red with New Rocker, Rob's pick on 2026-09-30 over the first night sea/gold look), `neon` (Kix in the Neon Night Market, black-violet/magenta/cyan with VT323 pixel headings, Rob's pick on 2026-09-30 over Audiowide) and `robot` (Rivet on Planet Cog, Scrap heap tin grey/copper/patina green with Black Ops One, Rob's pick on 2026-09-30 over gunmetal/lime with Tilt Warp). Avoid uppercase-only display fonts (Bungee, Rubik Mono One): Rob doesn't want all-caps labels. Picked in the side panel (pref key `...-skin`) or forced with `?skin=`. A theme can set `display-size` (default 1) to scale headings when its display font runs small (neon's VT323 uses 1.4); `applySkin` resets it for skins without one. The CSS `:root` defaults, the `skinFonts` link, the `theme-color` meta, the manifest colors and the icon colors in `tools/make_icons.py` all mirror the mall theme, so change them together; every color is a variable, so add new colors as theme variables, not hex in rules.
- Six shop slots, unlocked in order. Numbers per slot live in `SCHEMES` (cost, growth, payout, run time, automate cost). Names, icons, nouns and story text per episode live in each skin's `episodes`. Costs grow geometrically, milestones at 10/25/50/100/150 customers double a shop's income and give 1 beer. Upgrades (added 2026-09-30, from the first sketch doc): `UPGRADES` gives each shop 3 one-off cash buys in order, each x2 income, costing 600/6,000/60,000 x that shop's automation cost (so episode scaling and the discount card apply); `sc.up` counts them and resets each episode. The Upgrade button sits beside Buy and Automate, shows once the shop has a customer and hides when all 3 are bought; the customer count shows " · x4". Rob chose the middle option on balance: upgrades should speed engaged players up a little, not be free power and not be offset elsewhere. They launched at 150/1,500/15,000 (about 10% faster, episode 1 in 23 minutes); on 2026-10-01 Rob asked for episode 1 back near 26 minutes, so prices went x4 (episode 1 25 minutes, later episodes 2 to 4% faster than without upgrades). The greedy simulator only buys the cheap early shops' first upgrades in episode 1 (3 of 18), because later shops' upgrades never pay back in time.
- Prestige = episode finale. Needs `GOALS_NEEDED` (5) of the 9 goals (this episode's story goal plus 8 shared `GOALS`) plus one customer of the sixth shop. Resets cash and shops; keeps beer, eggs, crystals and cards; gives 3 eggs and multiplies the permanent income bonus `S.perm` by 1 + `finaleGain()` (x1.5, x2 at finale card level 5, x2.25 at level 10). The next episode starts with the first `FREE_AUTO_SHOPS` (1) shops automated (added 2026-09-30, see Balance target). It multiplied from 2026-09-29; before that it added +50%, and old saves just keep whatever `perm` they had.
- Episodes: five per skin (mall: Haunted Mall, Swamp Market, Crypt Quarter, Midnight Carnival, Sunken Casino; starport: Docking Ring, Hydroponics Deck, Reactor Row, Zero-G Stadium, Pirate Moon; ship: Barnacle Harbor, Smuggler's Cove, Skull Island, Floating Fair, Treasure Reef; neon: Gutter Street, Rain Bazaar, Chrome Row, Overdrive Circuit, Skyline Tower; robot: Scrapyard Flats, Toaster Works, Server City, Spark Festival, Old Spaceport), then they repeat ("Haunted Mall 2"). Each finale's last line hands off to the next district, and episode 5's leads back to episode 1, so adding an episode means rewriting the previous finale's ending. All episodes share the same `SCHEMES`, but customer costs, automation costs and goals marked `scaled: true` (the cash goal, `{$}` in its text) multiply by `costMult()` = `EPISODE_COST_GROWTH ^ episode` (2.5, so x2.5, x6.25, x15.6, ...).
- Cards level 1 to 10 by duplicates (`LEVEL_AT`: 1, 3, 6, 11, 19, 28, 38, 50, 64, 80 copies) and survive resets. Each is one multiplier, strength per level in its `per` field, applied through `cardBonus(id)` in the Math section (the simulator mirrors those formulas). Levels 6 to 10 were added on 2026-10-01 at Rob's request, because every card was maxed by about episode 12 and chests then only paid crystals; they count `LATE_LEVEL_STRENGTH` (0.5) each (`levelStrength`), because at full strength the maxed finale card (x2.5 per finale) matched the x2.5 cost growth and episode length stopped growing at about 5 hours. Now cards are nearly all maxed around episode 25. `perk` takes the bonus (from `bonusAt(id, level)`), not the level. Card ids are the effect: `money` all income, `speed` run speed, `discount` cost discount, `finale` finale bonus, `milestone` milestone multiplier (2 + bonus), `beer` milestone currency per milestone (1 + bonus; beer can be fractional and shows rounded down); the skin says who is on each (mall: Grizzle, Mort, Countess Vex, Bramble, Old Bog Witch, Fang). Six cards on purpose, so the card grid fills rows of 2 and 3 evenly; chests go three across or stack, never 2 + 1. Saves from before skins used the mall cast as ids and are migrated in `load()`. Rob prefers multiplier cards (speed, money, finale bonus) over rule-changing perks like free automation or offline caps. Saves from before this (no `cardsV2`) keep shops Mort used to automate. Chests: egg (2 eggs, 3 cards), beer (5 beer, 2 cards), crystal barrel (12 crystals, 4 cards). Duplicates of maxed cards give crystals. Daily chest (added 2026-09-30): once per local calendar day the `DAILY_CHEST` (egg) opens free; `S.dailyDay` holds the last day used and survives finales. A new game starts with today used, so the first free one comes on day 2 and episode 1's balance is untouched; old saves get one right away. It's not a fourth chest tile (that would break the 3-across rule); the egg chest's button says "Open free" and the Cards dot and welcome-back popup mention it. The simulator adds one per 24 hours of elapsed time (`DAILY=0` turns it off); it only nudges idle players' card levels.
- Sound: a small Web Audio synth in the Sound section (`sfx(name)` plays one of `SOUNDS`: tap, cash, buy, milestone, automate, goal, chest, finale). Notes are steps in the skin's `sound` scale, so each skin has its own voice. Automated shops are silent on purpose. Audio only starts after the first tap or key (browser rule); mute pref key `...-sound`, an on/off switch (`#soundBtn`, `role=switch`) above the volume sliders in the side panel. Ambience: each skin's `sound.ambience` names a recipe in `AMBIENCES` (Ambience section), a steady bed of hums and filtered noise plus random events on timers, built with the small kit in `ambienceKit()`; it fades in, restarts on a skin change, and stops while muted, at zero volume or while the tab is hidden. Effects and ambience have their own buses and sliders in the side panel (pref key `...-volume`, `{fx, amb}` 0-100, defaults 100 and 50, gain is the square). The pane can't be heard, so check a loop by connecting an AnalyserNode to `__game.amb.out` and measuring RMS (the five sit around 0.02).
- Art: the Art section's `ART[skinId]` holds hand-drawn inline SVG: `cards` (a 64x64 portrait per card id, replacing the emoji; cards not found yet show it as a dark silhouette) and `scenes` (a 480x180 banner per episode, shown at the top of that episode's intro and finale). `shops` holds a 48x48 icon per shop, one row of six per episode, drawn on a transparent background over the shop's colored tile (bolder outlines, 2px, because they show at about 52px). `render()` only rewrites an icon button when its skin, episode or shop changes (`r.iconKey`); rewriting a button every frame would drop taps. Skins without art keep emoji. Style: flat shapes, a dark outline (`O`), the skin's palette, a halo circle behind each portrait. Ids inside SVGs must be unique on the page (prefix `art-<skin>-...`). All five settings have all six portraits, all five scenes and all 30 shop icons (2026-09-30), with the owner in every scene: the mall (Grizzle), Starport Nine (Juno), The Salty Gull (Nell), Neon Night Market (Kix) and Planet Cog (Rivet; its whole cast are robots). Chest results show a small portrait next to each card when the skin has art. Scenes are generated by small Python scripts with helpers for the owner and recurring cast (a head at a position and scale); the SVG strings end up in `ART`. Rob approved this style on 2026-09-30 and wants it for every other setting: flat shapes, outline `O` at about 1.4 (thinner on details), the setting's theme colors plus natural character colors, gradients only as soft glows around light sources. Portraits are head and shoulders with big glowing eyes and one signature prop each. Scenes are layered night scenes with that episode's story props, and the setting's owner appears in every scene. Preview scenes large and make sure no character is hidden behind a prop.
- Rivals: each setting's `milestone` card is the owner's rival (mall: the Old Bog Witch; Commodore Glint, Captain Blackwake, Mr. Glass, Chairbot Prime) and runs through that setting's story. The Witch is introduced in episode 1's intro (fortunes from the old candle shop across the atrium) and appears in four of the five mall scenes (her shop window, across the swamp, the carnival tent's eyes, the mausoleum door, the casino card table). Every rival appears in all five of their setting's scenes and in every episode's story (done 2026-09-30; Mr. Glass got a Rain Bazaar intro line to fill the one gap). Figures added that day (the Witch in the atrium, crypt and casino; Glint in an office window, behind the hot spring with the deed, in the stadium stands; Blackwake in a rowboat three times; Glass in two tower windows and driving an armored truck; Chairbot Prime in Toaster Works, Server City and at the festival) are the rival's card portrait scaled into a `<g transform>` with thicker strokes, so they match the card exactly. The rival portraits contain no SVG ids, which is what makes reusing them safe.
- Story goals (2026-10-01): `STORY_GOALS` has one goal per episode slot (`S.episode % 5`): 50 customers at the second shop, 3 upgrades, 25 customers at 4 shops, 12 milestone bonuses, 150 customers at the first shop. Each skin episode's `goal` field is a short line on why it matters in that story, shown in italics under it. `goalsNow()` puts it first; it counts toward the 5 like any goal and pays the same egg. Shared goal h2 (10 customers at the third shop) was removed to make room, so eggs per episode and engaged times stay the same; with it kept, the extra egg made later episodes 4-11% faster. Casual players lost a visit in episodes 8 and 12 (the 4-shops and upgrades story goals are harder for them than h2 was); the welcome-back bank bonus won it back. `STORY=0` leaves them out of the simulator.
- Story: a `<dialog>` shows an intro per episode (once, tracked by `S.storySeen`, the number of the last episode whose intro was shown; -1 shows episode 1's again) and a finale scene when the finale button is pressed.
- First-tap tip: in episode 1, until the first shop can afford its second customer (and isn't automated), `#hint` floats as a fixed bubble at the bottom of the screen. It's fixed on purpose so showing and hiding it doesn't shift the layout (Rob's request, 2026-09-30); toasts sit above it (`z-index` 5 vs 4).
- Welcome back: `offline()` credits automated earnings; after a break of `WELCOME_AFTER_S` (5 min) or more it opens a popup (`welcomeBack`) with the time away, the earnings, chests ready to open and whether the finale is ready; shorter breaks get a toast. Since 2026-10-01 (idea #2 from Rob's list, "something to decide on welcome back") the popup asks: Bank (earnings + `BANK_BONUS` 25%) or Rush hour (all income x`RUSH_MULT` 3 for `RUSH_S` 300 s, wall clock, in `S.rushUntil`; `rushMult()` is in `globalMult()`, so every income number shows it; `offline()` divides it back out; it carries over a finale). The earnings are credited before the popup, so closing it with Esc keeps them without a bonus. The countdown sits in the episode line (`#rush`), so it never shifts the header. Banking wins after long breaks (25% of hours of earnings vs 10 extra minutes of income), a rush when you're back to play; the simulator's session players always bank (`BANK=0` turns it off). Both are equal buttons (`choice: true` in a story action gives the second one full button styling). Popups share the story `<dialog>` and queue (`storyQueue`) if one is already open, e.g. an episode intro on load.
- Saves: localStorage key `grizzle-haunted-mall-v1` (game; the name predates skins and stays for old saves), `...-buymode`, `...-view`, `...-skin`, `...-sound` and `...-volume` (UI prefs, kept separate so resets don't wipe them). Offline earnings are credited on load and when a background tab becomes visible.
- Save codes (2026-10-01): the side panel's Save row has Copy, Paste and Wipe. Copy puts `MSI1.` + base64 of the save JSON on the clipboard (or shows it in the story dialog if the clipboard is blocked, as in the browser pane); Paste takes a code in the story dialog, checks it with `readSaveCode`, which runs the same `parseSave` migrations as `load()`, asks to confirm with both games summed up, then credits the time since the code was copied as time away. Rob plays on two computers, which is why it exists.
- URL flags: `?speed=10` runs faster, `?skin=starport` forces a skin, `?debug` exposes `window.__game` (state, skin, `setSkin` and a few functions).

## Balance target

Episode 1 should take about 30 minutes; the simulator (greedy, always-tapping player) currently gives about 25 minutes (26 without upgrades), with the fifth goal clearing a few minutes before the dragon lease. Later episodes deliberately get longer (Rob chose a long tail): engaged players take about 26, 30, 37, 45, 56 minutes, then 1.1, 1.4, 1.7 and 2.0 hours for episodes 2 to 10, 2.8 at 12, 8.9 at 20 and 16.6 at 25 (+20 to 25% per episode early, about +12% once cards pass level 5). Real players are slower. If you change costs or goals, rerun the simulator and update the README numbers.

The simulator also plays casual (10 min every 2 h) and idle (3 min, 3x a day) profiles. Early episodes finish on the second session because income grows exponentially and one break's offline earnings cover the rest of an episode; lowering the offline rate barely helps (even 1% still finishes in 2-3 sessions). On 2026-09-29 Rob chose the long tail over a time gate or accepting it: per-episode costs multiply by 2.5, so idle players take 8 hours per episode for episodes 1 to 5, 16 hours for 6 to 8, then 1 day. The finale bonus used to add +50% per episode, which against x2.5 costs made a wall (time doubling each episode past 8, 12 days by episode 12); on 2026-09-29 it became multiplicative (x1.5 per finale), which keeps the tail gentle. Costs still outpace it slightly (2.5 vs 1.5 to 2), which is the intended slow growth.

Idle tuning pass (2026-09-30): the simulator's session players used to tap every shop the instant it finished; with a realistic few seconds between taps, idle players started each later episode with nothing automated, earned nothing while away, and needed more and more visits to afford the first automation (500 x the episode's cost multiplier): 1.3 days for episode 5, 6.7 days for episode 12. Starting episodes 2+ with the first shop automated (`FREE_AUTO_SHOPS`) fixed it: idle is now 16 hours for episode 1 (a new player's first 3 minutes can't automate much), 8 hours for 2 to 5, 16 hours for 6 to 11, 1 day at 12; casual is 2 hours through episode 8, then 4; engaged is unchanged.

## Testing notes

- The in-app browser pane can't run page tools on `file://` URLs. Serve the folder instead (`python -m http.server 8770`, then open `http://localhost:8770/index.html?debug`) and stop the server afterwards. The pane caches the page, so after editing add a throwaway query (`&v=2`) when reloading, or you'll test the old code.
- Automated clicks are instant, so they miss bugs that only happen during a held press. `left_click_drag` from a point to 1px away gives a realistic held press.
- Background tabs pause `requestAnimationFrame`, so taps and income look frozen if the preview tab isn't in front. Front the tab or test functions directly through `?debug`. If the pane itself is hidden, frames stay paused even for the front tab; taking a screenshot makes it render.
- A `beforeunload` handler saves state, so injecting a save then navigating gets overwritten. Override `Storage.prototype.setItem` first if you need to test loading a crafted save.
- Quick syntax check: pull the `<script>` block out of `index.html` into a `.js` file and run `node --check` on it.
- Look comparisons: a throwaway `_palettes.html` in the repo root with one iframe per option (`index.html?skin=X&debug`); on load each frame runs `Object.assign(g.SK.theme, theme); g.SK.hues = hues; g.setSkin(id)` through `__game`. Screenshot only after the frames have loaded (early shots show the old theme), and delete the file afterwards.
